# Stack Lang

Учебный проект: небольшой язык выражений и операторов, компилятор в байт-код
стековой машины, пошаговая виртуальная машина и GUI-визуализатор.

Нужен Python 3.10+ (проект проверялся на 3.13).

Проект специально разделён на два независимых слоя:

- **core** — язык, компилятор, байт-код и VM;
- **gui** — Tkinter-представление, которое только читает состояние и вызывает
  методы контроллера. Логика языка в UI не вшита, поэтому GUI можно заменить
  на PySide6, web или что угодно без переписывания компилятора.

## Быстрый старт

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m gui
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m gui
```

`tkinter` входит в стандартную библиотеку Python. На Linux может понадобиться
системный пакет `python3-tk`.

## Что уже работает

### Язык

- целые десятичные литералы (`42`, `007`);
- идентификаторы, включая Unicode;
- арифметика: `+`, `-`, `*`, `/`, `%`, `^`;
- целочисленное деление с усечением к нулю и остаток в стиле C;
- постфиксный факториал `!`;
- унарные `+`, `-`, `!`;
- сравнения: `<`, `>`, `==`, `!=`, `<>`, `<=`, `>=`;
- логические `&&`, `||` (результат `0`/`1`);
- скобки;
- вызовы встроенных функций: `abs`, `min`, `max`, `sqrt`;
- присваивание `имя = выражение;`;
- выражения-операторы;
- `if` / `else if` / `else`;
- `while`;
- блоки `{ ... }`, в том числе как самостоятельный оператор.

Пример:

```text
n = 5;
result = 1;
i = 1;
while i <= n {
    result = result * i;
    i = i + 1;
}
```

### Компилятор и VM

Компилятор однопроходный: разбирает символы исходника и сразу выпускает
байт-код. AST не строится, лексера нет — это осознанное упрощение для
учебной задачи про стековую машину.

Опкоды: `PUSH`, `LOAD`, `STORE`, `POP`, `NEG`, `NOT`, `JZ`, `JMP`, `CALL`,
`FACT`, `ADD`, `SUB`, `MUL`, `DIV`, `MOD`, `POW`, `AND`, `OR`, `LT`, `GT`,
`EQ`, `NE`, `LE`, `GE`.

`Machine` умеет выполнять код по одной инструкции (`step`), целиком (`run`),
сбрасываться (`reset`) и отдавать снимок состояния (`snapshot`). Это и есть
точка, через которую GUI делает дебаггер.

### GUI

Запуск:

```bash
python -m gui
```

Что есть:

- редактор исходника с подсветкой текущей строки;
- режим «Программа» / «Выражение»;
- байт-код с PC, операндом и номером строки;
- подсветка текущей инструкции;
- стек с вершиной сверху;
- таблица переменных;
- панель вывода и ошибок;
- запуск, пауза, шаг, сброс, выбор скорости;
- брейкпоинты двойным кликом по строке байт-кода;
- примеры программ;
- открытие и сохранение `.lang`-файлов.

Горячие клавиши:

| Клавиша | Действие |
|---|---|
| `F5` | запуск / продолжение |
| `F6` | пауза |
| `F10` | один шаг |
| `Ctrl+Enter` | компиляция |
| `Ctrl+R` | сброс |

### CLI

```bash
python stack_compiler.py --run "1 + 2 * 3"
python stack_compiler.py --run "x=41" "x + 1"
python stack_compiler.py --run "i = 0; while i < 3 { i = i + 1; }"
python syntax_check.py "a + b * (c - 1)"
```

## Структура

```text
testPO/
├── stack_compiler.py      # core: компилятор, байт-код, Machine, CLI
├── syntax_check.py        # отдельная проверка синтаксиса выражений
├── classInt.py            # учебный прототип таблицы символов
├── gui/
│   ├── __main__.py        # python -m gui
│   ├── app.py             # только Tkinter-виджеты
│   ├── controller.py      # DebugSession, без tkinter
│   └── examples.py        # примеры программ
├── test_*.py              # pytest
├── requirements.txt
└── README.md
```

Граница слоёв: `gui.controller.DebugSession` — единственное место, где UI
встречается с core. Контроллер не импортирует Tkinter, поэтому его поведение
тестируется обычным pytest. `gui.app` не содержит правил языка.

## Тесты

Команды ниже выполняются после активации `.venv`.

```bash
python -m pytest -q
```

Покрыто:

- приоритеты и ассоциативность операций;
- генерация байт-кода;
- выполнение выражений и программ;
- `if` / `else if` / `else`, `while`, блоки;
- переходы и патчинг адресов;
- ошибки компиляции и runtime;
- позиции ошибок;
- `Machine.step`, `reset`, `snapshot`, лимит шагов;
- `DebugSession`: компиляция, шаги, брейкпоинты, снимки;
- CLI;
- smoke-тест GUI (пропускается без дисплея).

Покрытие:

```bash
python -m pytest --cov=. --cov-report=term-missing
```

## Известные ограничения и TODO

Язык:

- нет объявлений `int x;` и статической семантики — переменные создаются
  присваиванием;
- нет областей видимости;
- нет пользовательских функций, рекурсии и `return`;
- нет комментариев;
- нет `print`/`input` и строк;
- `&&` и `||` имеют одинаковый приоритет и не замыкаются коротко;
- нет `break`/`continue`/`for`;
- `^` неассоциативен (`1 ^ 2 ^ 3` — ошибка).

Инфраструктура:

- `syntax_check.py` пока не полностью повторяет грамматику компилятора
  (например, не знает вызовы функций и `^`);
- `classInt.py` — отдельный учебный прототип, в компилятор не интегрирован;
- брейкпоинты в GUI ставятся по инструкциям, а не по строкам исходника;
- GUI не умеет step over/into: пользовательских функций пока нет;
- нет CI и автоматического coverage-порога.

Ближайший порядок работ:

1. Синхронизировать `syntax_check` с компилятором.
2. Добавить объявления переменных и области видимости.
3. Добавить пользовательские функции и кадры вызова.
4. Добавить комментарии и `print`.
5. Добавить source-level брейкпоинты и step over.
6. Подключить CI и coverage-порог.
